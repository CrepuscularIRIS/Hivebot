## P-D：设置·Bot 配置
### 核心旅程与信息层级
- 会话头部「配置」→ 查看当前 bot → 改模型，或「用此配置新建」→ 原建 bot 对话框预填 → 创建并进入新 bot。
- 最易卡住：用户以为安装后可直接给旧 bot 加工具；固定配置说明紧贴连接器区，不藏在 tooltip。
- 首要信息是「这是哪个 bot、配置是否可用」；第二层是 preset／连接器；模型和主 bot 设置放后。
- 标题固定「Bot 配置」，显示 bot 名；不叫笼统「设置」，避免误认为全局偏好。
- 原版七节导航不照搬：本期不存在的 general／permissions／vault 等直接不出现，不做灰色占位。

### 布局草图
```text
┌ Bot 侧栏 ┬ ← 返回会话         Bot 配置              ┐
│ 主 Bot   │ Bot 名称                     主 Bot 标记 │
│ Bot X    │ [失效时：连接器已失效，请新建 bot]        │
│ Bot Y    │ 基础配置    preset 名称（只读）           │
│          │ 连接器      A、B（只读；无则「未使用」）    │
│          │ 配置随 bot 固定，换配置需新建。           │
│          │ [用此配置新建 →]                          │
│          │ 模型        [当前模型／默认值 ▾]          │
│          │ 主 Bot      [设为主 Bot]／「当前主 Bot」    │
└──────────┴──────────────────────────────────────────┘
```
- 新建对话框沿用现有 modal：preset → 模型 → 已安装连接器 checkbox → 固定配置提示 → 创建。
- 连接器列表较长时仅列表内部滚动；底部错误与创建按钮始终可见。

### 交互细节
- 普通 bot 的 preset／连接器只有文本，无铅笔、假开关或「保存配置」；模型明确提示「仅影响此 Bot」。
- 「用此配置新建」只预填基础 preset、连接器与可确认的模型，不复制历史、不自动提交。
- 预填项仍须对照 #1/#2/#16 校验；已不可用的连接器保留名称并标注，禁止静默丢掉后创建。
- 未知配方不得猜测原配置：保留新建入口，但打开后要求明确重选，说明「原配置无法完整恢复」。
- 候选仅来自 #16 的实际已安装 bundle；不能把目录条目或仅列在 inventory 中的未安装项算进去。
- #16 加载失败不当成零连接器；保留预填选择、显示重试，避免用户无意创建成无工具 bot。
- 模型选择提交中禁重复操作，成功后更新显示；失败保留原模型并就地报错，不伪报已切换。
- 设主 bot 经 M3 patch 成功才更新置顶；当前主 bot 无删除入口，不自动更换失效主 bot。
- 创建中只显示「创建中…」，不发明百分比；创建成功但模型失败显示「Bot 已创建，模型未切换」，不再次创建。

### 状态全集与 D10c
- 加载：只替换未知字段为短骨架，已知 bot 名／历史不消失；连接器加载与「未使用连接器」分开。
- 空：连接器为零时显示「尚未安装连接器」＋「前往市场」；从新建对话框过去要保留已有选择。
- 错误：字段级请求失败留在对应区域；创建失败保留输入，不把孤儿 recipe 显示成 bot。
- 离线：沿用现有断线提示，可读配置与历史；禁模型修改、设主 bot、创建，不把离线判成连接器失效。
- **D10c1，独立交付**：由 header/preset＋M3 recipe.live 判只读，复用 botInfo；缺 recipe 也按只读处理。
- c1 文案固定「连接器已失效，请新建 bot」；历史可读、composer 禁发送；不自动重试、不先发消息探测。
- c1 失效是 bot 级持久提示，不是会消失的 toast；其他 bot 操作不受阻，无证据时不点名某个连接器。
- **D10c2，依赖 U-14/T-16**：验证启动 allSettled／超时隔离与 live=false；不另做一种「c2 UI」。
- 启动恢复未完成沿用 boot cover；后端没有逐配方进度字段，就不展示「正在恢复第 N 个」。
- 需要审批：仍在原会话卡作答；配置页不加第二套批准按钮，失效提示也不复用审批黄点。

## P-C：市场
### 核心旅程与信息层级
- 侧栏「市场」→ #12 选择已有目录源 → #13 搜索 → #14 详情 → #15 安装 → #16 确认 → 新建时勾选。
- 最易卡住：「已安装」被误解成「已有 bot 已启用」；安装前后持续说明「安装后，需在新建 Bot 时选择」。
- 首屏首要信息是条目能否安装及原因；来源／版本次之；不拿可见数量制造「都能用」的承诺。

### 布局草图
```text
┌ Bot 侧栏 ┬ ← 返回           市场                    ┐
│          │ 插件                                      │
│          │ [浏览] [已安装]        [搜索插件…]         │
│          │ 目录源 [已配置来源 ▾]（仅浏览时）          │
│          │ 名称／简介           状态／查看详情 →     │
│          │ 名称／简介           仅供浏览             │
│          │                    [加载更多]             │
└──────────┴──────────────────────────────────────────┘
详情替换列表主区：← 返回结果／名称／版本／说明／安装状态／底部主动作
```
- 保留原版顶栏与 tabs 语言；只做 plugins 范围，「浏览／已安装」是插件内子导航，不冒充原版 bots tab。
- 详情返回保留来源、query、已加载结果与滚动位置；不新增页内第三列或叠套 modal。

### 交互细节与 T-19 分野
- #12 来源只读可选，无新增源、setIndexes、自定义 MCP、全局启用／禁用入口。
- 搜索小幅防抖；切源／改 query 重置分页；迟到响应不能覆盖新来源或新搜索的结果。
- **90 无坐标**：按 keywords 中精确 `not-installable` 标记禁安装；保留详情，正文说明「此条目暂无可用安装坐标，仅供浏览」。
- 禁用原因常驻可读，不只放在禁用按钮 tooltip；有 install.spec 也不得覆盖该标记。
- **21 有坐标不等于 21 可用 bundle**：显示「安装」，详情说明「安装时仍需校验 dsh bundle 兼容性」。
- 使用响应所给版本 install.spec，不从展示 title／server 名拼包名；缺安装目标则禁安装并说明。
- T-19 已证实裸包可能报 not-bundle；这种失败须直说「此包不是受支持的连接器包」，不能改称网络故障。
- #15 固定 enabled:false；检查实际安装业务结果，不能仅凭 M1 ok:true 就显示成功。
- 成功后重拉 #16 核实实际安装状态，再显示「已安装，尚未用于新 Bot」及「用此连接器新建」。
- 新建入口复用 P-D 对话框、预选此连接器但不提交；旧 bot 不增工具，全局不启用。

### 状态全集
- 加载：列表骨架与详情骨架独立；分页加载保留原条目；安装期间仅对应动作忙碌，不锁整个市场。
- 空：未配置源／搜索无结果／尚未安装三种文案分开；无搜索结果提供「清空搜索」，不显示安装 CTA。
- 错误：源失败可切其他已有源；详情失败可回列表；安装失败显示分类原因和手动重试，不静默重复安装。
- 离线：保留当前已读内容并注明「连接已断开」；禁安装与新建，恢复后先核对 #16 再决定能否重试。
- 长任务：显示「正在安装…」，允许离开页面；不提供契约没有的取消、日志流或假进度条。
- 安装时断链／响应丢失：显示「安装结果尚未确认」，禁止自动重发；#16 只能确认已装，不能证明安装已结束。
- 需要审批：不预设安装必审批；如既有 $events 真下发请求，沿用原卡及所属 bot 定位，不加「始终允许」。
- Token：中性列表底、细分隔线、14px 行文、12px 状态；详情与按钮沿用 modal/menu 的 8–16px 圆角和 XVF。
- 原版差异：不做分类墙、技能、发布、同步与账户连接；接口和范围不支持的入口不造景，远程图片不加载。
