## 根因（不是派发怀疑的「释放把 running 也算了」，是收养侧丢失）
trackWorkerTurns 在 slots.reserve() 失败（满额）时直接丢弃该 turn/start：
worker 实际 running 但不在 holds 也不在任何账上。此后任一持位 worker 的
turn/end 释放一格 → used 下降，而仍在 running 的溢出 worker 永远不会被补记
→ 3 running 只计 2，create_bot reserve 成功、main 实发建 bot 请求。

## 修法（app/sdk/src/orchestration/slots.mjs，两处释放路径一处挂钩）
- 满额未收养的 worker 记入 pending（Set）；turn/start 查重加 pending。
- Slots.release() 末尾调 onFree?.()；trackWorkerTurns 挂补收养（释放后收养
  最早的 pending）。create.mjs 的 release 与 trackWorkerTurns 的 turn/end 都
  经 Slots.release()，故 create 路径释放同样补收养（有独立单测）。
- 不变式：pending 非空 ⇔ used == limit；pending 中提前 turn/end 的 worker
  只出 pending、不释放（没占过格子）。create.mjs 零改动。
