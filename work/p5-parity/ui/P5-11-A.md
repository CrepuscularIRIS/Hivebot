## 1. 核心旅程
1. 打开 → 侧栏头部一行 3 个 icon：`[◧ collapse] [⌕ search] … [+ New Bot]`（左两枚贴左，New Bot 贴右，见 §4 理由）。
2. 想找某个 bot：焦点在侧栏（点过某项 / Alt+↑↓ 后）直接敲字母 → 头部**原位**变成搜索框，首字符已在框里，列表即时过滤。
3. Enter → 打开第一条匹配并退出搜索；或 ↓ 进列表用 ↑↓/Enter 选。
4. Esc → 一次清空并退出，列表恢复、焦点回 search 钮。
- **最容易卡住**：「敲了字但什么都没发生」（焦点不在侧栏，或输入法组合中）。解法：search 钮 tooltip 写「搜索（在侧栏中直接输入）」，把隐式入口说出来；IME 组合中（`e.isComposing`）不触发，避免吃掉第一个拼音字母。

## 2. 信息层级
- 常态：列表是主角，头部只是 3 枚 24px 灰 icon，不抢眼。
- 搜索态：搜索框是唯一焦点；结果数不常显，只走 `role=status` 读屏（视觉上列表本身就是结果）。
- 折叠态：只剩头像 + 角标，名字靠 `title` tooltip 和 `aria-label`。

## 6. 宽度与持久化（只动 `Resizer.tsx` + `Sidebar.tsx`，不改 App.tsx）
- `ColumnSpec` 加可选 `compact?: number`。`readColumn` 接受 `v===compact`；拖拽时 `w < (compact+min)/2` → 吸附 compact，否则 clamp 到 [min,max]；键盘 ← 在 min 处 → compact，→ 在 compact 处 → min；`aria-valuemin=compact`。info-pane 不传 compact，行为不变。
- collapse 钮：`onWidth(compact, true)`；展开：`onWidth(lastExpanded, true)`，`lastExpanded` 用 ref 记最近一次 >130 的宽，冷启动在折叠态时退 `SIDEBAR.initial`（ponytail：不另存 expandedWidth 键，需要「重启后展开回原宽」再加 `sand.sidebar.collapsed`）。
- 钮的 aria：`aria-label="收起侧栏"/"展开侧栏"`、`aria-expanded`，由 `width <= 130` 推（JS 只管 aria/title/头部渲染，几何全交容器查询）。
- 折叠态条目加 `title={info.name}`（仅折叠态，展开时不加，避免重复 tooltip）。

## 7. 反提案
**不要做常驻的全宽搜索框**（0.18 的 `SandButton md` 全宽钮、或「列表顶上永远一个 input」）。大家默认会这么做，因为「搜索要好找」。但：① R2 实测 0.78.1 已改为头部 icon，BRIEF 目标是 0.78.1；② 我们的 bot 数量级是个位到几十，常驻框为低频动作永久占掉 40px 列表高度；③ 常驻 input 会抢可打印键语义（焦点在框里时 Alt+↑↓、Enter 冲突）。替代：icon + 「在侧栏直接打字」隐式入口 + **原位展开**（头部高度不变，列表不位移，Esc 回来零跳动）。

次要反提案：**不要在新位置另起一行搜索栏**。插行会把整个列表下推 32–40px，Esc 再弹回，用户眼睛追不上刚才看的那一项。
