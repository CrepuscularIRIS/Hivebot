## 必须回应清单（P6-24 开工时转成验收项）

1. **[HIGH·A] 指令文件注入绕过污染守卫**：worker 写的 `AGENTS.md` / `CLAUDE.md` 会被 agent-instructions 当作指令送进主 bot（`config.ts:11-12`、`state.ts:85-88`），而污染判定只认 `pbots-worker` 来源（`turn-origin.mjs:11`）——等于绕过决策 29。worker 的 write/edit 写这两类文件一律拒；bash 写同名文件的残余风险标 `ponytail:`，并写进给用户的告知。
2. **[HIGH·A] 未迁移的旧主 bot**：主 bot 是 P5-25 之前的旧 bot（P5-26 迁移仍 blocked）时，其 cwd 可能是仓库或 SDK 目录，worker 会落进去——正是 C2-② 要防的（`orchestrate.ts:4-6`）。主 bot cwd 不在 `workspaces/<mainId>` 下 → fail closed，不派。
3. **[HIGH·B] 同文件并发覆盖**：现验收⑥只测两个 worker 写不同文件。最低限度按文件划分写入责任；划分不了的任务串行，不以「原版也如此」为控制措施。补同文件并发用例。
4. **[HIGH·B] 影响面扩大须告知**：单个 worker 从只能破坏自己的目录，变为能改发起者的全部文件；被外部不可信内容诱导时波及面更大。写进给用户的签字题；用 P6-24⑤ 证明无关 bot 仍不可写。
5. **[MEDIUM·B] 删除边界作为硬门槛**：删 worker 后发起者目录的完整文件清单不变（验收④），worker 生命周期不得拥有共享目录删除权。

挂载面（席 A 补充）：隔离按 `header.cwd` 判（`guard.mjs:14-16`），worker 是**替换**为主 bot 目录而非叠加，bwrap 挂载面本身不变大。
