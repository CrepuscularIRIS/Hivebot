## 2. 通用约定（全部任务适用）
- **测试**：fake LLM 驱动工具调用（`app/sdk/tests/support/fake/plugin.mjs`）；SDK 侧 launcher 复用 `app/sdk/tests/support/runtime.ts`；UI 侧 playwright `_electron`，重启只用 `electronApp.close()` 再 launch。L-UI 用 `HOME=/tmp/bot-p5-<id>`；L-AP 沙箱类用决策 8 的路径。
- **正对照分两类**（v2，B §6 细化）：每条「看不见 / 写不进 / 连不上」探针在验收表里标明类别并写死两侧期望。**差分对照**（新增防护）：stock profile（不配 `runnerCommand`、不挂 guard）下该探针**本身**命中（文件可见 / 连接成功 / guard 位置出卡或成功），加固后不命中——逐探针成对，不接受「组内至少一项」。**既有防护命中**（stock 已拦，如私有 `/tmp`、工作区外写 EROFS、web_fetch 只放公网）：两侧都断言同一个确切错误，报告里标「既有防护，不计入本 slug 防线」。探针只做存在性 / 连通性检查，不读真实凭证内容。
- **网络探针口径**（v2 写死）：用 `/usr/bin/python3 -I -c` 小探针输出结构化结果（不用 curl 退出码）：loopback TCP（`127.0.0.1:4001`、gateway base-url、`127.0.0.1:20000`）加固后 `ConnectionRefusedError` errno === 111；外网域名解析加固后 `socket.gaierror` errno ∈ {-3, -2}（R5 实测 -3，`reuse/r5-sandbox-probe.md` §②）；stock 下 loopback 探针连上探针现场起的 stub（不打真实 LiteLLM 内容，只 connect）。本条 127.0.0.1 探针只对 `--unshare-net` 态有意义；联网升权态的 loopback 探针（网关别名、代理 CONNECT、`localhost`）见 P5-22 ②（v2.1）。文件探针：`test -e` / `test -S` 退出码；写入失败断言 errno ∈ {EROFS, ENOENT, EACCES} 中按探针写死的一个。
- **断言口径**：精确值或显式枚举集合；「没有出卡」= `approval/asked` 计数 === 0；「dsh 没收到」= main 侧 `/api` 计数 === 0；不写「被拒或不可见」二选一——每格写死期望（bash → 不可见 + errno；文件工具 → deny + 原因）。
- **进程**（CLAUDE.md §5）：测试只在 teardown 里结束自己 spawn 的子进程；agent shell 不手工 kill，不用 pkill / killall / -P。
- **合并**：每次合入 main 后跑所在包全量（app/sdk → `pnpm -C app/sdk test`；app/ui → build + 单测 + e2e），绿了才算合并完成。P5-01、P5-02 碰 SDK 启动链，合入后**两个包都跑全量**。evidence 只放报告、脚本、frames，运行时目录用后即删。
- **报告位置**：VERIFY / evidence 一律写主仓 `/home/lingxufeng/bot/work/p5-parity/…`，不写 worktree 内的 `work/`。
- **清单闭环**（v2，G2-r1 #9）：任何任务、任何时候发现一条凭证路径不在 `never-roots.mjs` 覆盖内 → 开一个 `.f`，**只改 `never-roots.mjs`**（wrapper 与 guard 同时生效，决策 6），验收 = 该路径在 P5-01 ② 与 P5-02 ① 的探针表各加一行并绿；P5-06 在存在未关的此类 `.f` 时不得判 PASS。
- **TOCTOU**：guard 先 resolve、工具后打开，中间可被沙箱内 bash 并发换符号链接。接受，guard.mjs 写 `// ponytail: resolve→open 之间有 TOCTOU 窗口，需要时在 fs 层做 O_NOFOLLOW 或 post-check`。

## 5. 设计题（给主会话跑 /panel D，director 不定稿）

### D-1 受控升权路径（影响 P5-22、P5-31、Q-013 第 2 行）
**题干**：bash 和文件工具今天的升权只有一档 `danger-full-access`（`D/sandbox/sandbox/src/escalation.ts:30-31`），这一档直接跳过 confine，wrapper 不执行（`D/sandbox/bash-sandbox/src/index.ts:92-100`）。P5-04 把它（参数与部署模式）整体拒绝，且**在任何选项下都保留**。需要一条「放开联网，或多放开一个写目录，但凭证遮蔽始终保留」的路径。
**约束**：① pre-execute 只能返回 allow / deny / cancel / ask，不能改写参数或换执行器（`D/core/tools/src/contracts.ts:358-361`）；② 上游沙箱接口不表达网络维度（`D/sandbox/sandbox/src/index.ts:24-59`）；③ wrapper 只收到 argv 和 shell-env 环境（有 `DSH_SESSION_ID`，没有 callId）；**④（v2 新）联网升权之后 loopback 与本机服务仍不可达**：去掉 `--unshare-net` = 宿主网络命名空间，本机 127.0.0.1 上有 41 个监听端口（含 LiteLLM 4000/4001、CLIProxyAPI、代理端口），B A4b 会被打穿；可行做法需要用户态网络栈（pasta / slirp4netns，本机**未安装**；apt 安装需 sudo，但**静态二进制可免 sudo 由用户放 `~/.local/bin`**——slirp4netns 上游 release 提供静态二进制、pasta 可用户态编译，D-1 panel 前派 scout 核实）或宿主侧只放行公网的出口代理 + 沙箱内转发，两者都是新组件。**v2.1 补：宿主 loopback 的入口不止 127.0.0.1**——用户态网络栈下沙箱内的 `127.0.0.1` 是新 netns 自己的 lo，测它必然 errno 111，证伪不了任何东西；宿主 loopback 走网关别名：slirp4netns 默认 `10.0.2.2` → 宿主 127.0.0.1（关：`--disable-host-loopback`），pasta 默认网关地址 → 宿主 loopback（关：`--no-map-gw`）；出口代理可被 `CONNECT 127.0.0.1:<port>` / `CONNECT localhost:<port>` 打到本机。约束写成：直连、网关别名、代理 CONNECT（IP 与 `localhost` 字面量）到宿主 loopback 都不可达，所选组件的映射开关强制关闭；验收见 P5-22 ②（含关开关时必须命中的差分）。
**评判维度**（v2 新）：凭证与 loopback 两条不变量是否成立；模型是否知道何时、怎么用；实现量（含新组件、要不要用户装东西）；上游升级时的漂移面。
**选项**：
- ① **受控执行工具** `bash_elevated {command, network?:bool, write_dir?:string}`：复用同一 wrapper，按批准内容去掉 `--unshare-net`（并接入约束 ④ 的网络组件）或多 `--bind` 一个目录；每次 ASK、无始终允许。代价：模型可见的新工具（描述、snapshot、引导）；要自己实现执行（复用上游 shell 执行服务的程度待查）；约束 ④ 的新组件（v2.1：免 sudo，代价从「用户装东西」变为「pin 版本、进 MANIFEST、跟进上游安全修复」）。
- ② **wrapper 读一次性许可**，由对升权请求出卡触发：**在约束 ① 下不可行**——模型只能用 `danger-full-access` 表达「要联网」，而这一档跳过 wrapper；列出仅为完整，不建议席位重复论证。
- ③ **不做**：本 slug 内联网和写工作目录外一直不可用，Q-013 第 2 行写明；需要时另开 slug。代价：`pip install`、`git clone` 必须由用户在 bot 外做（B §4 死因 3）。
- ④ **向上游提 issue / PR**（网络维度、升权保留 confine），本 slug 内按 ③ 过渡。代价：时间不可控；上游 `has_issues=false`（`reuse/d2-mcp-meta.md` §0），只能走 PR。v2.1：①⑤ 的新组件不再需要用户 sudo，③④「不用装组件」相对 ①⑤ 的优势变小，席位按新代价重排。
- ⑤ **（v2 新）会话级联网许可**：注册只申请许可的小工具 `request_network{reason}`，每次 ASK；批准后 main 签发按 `DSH_SESSION_ID` 的限时许可文件（放 mask 根内，bash 不可见），wrapper 读到就放开外网（仍受约束 ④）。执行器仍是 bash，不用自写执行，也不经过 `danger-full-access`。代价：约束 ④ 的新组件；许可是会话粒度（窗口内所有 bash 都能联网），比 ① 的逐命令粒度粗；许可文件成为新的需遮蔽对象，且**依赖 mask 根已设**（许可文件放 mask 根内；v2.1 起 mask 根恒有值：`PBOTS_DATA_DIR` 或缺省，决策 15）；新组件同 ① 免 sudo。

### D-2 MCP 元数据桥（影响 P5-21、P5-23、P5-24、Q-013 第 7–9 行）
