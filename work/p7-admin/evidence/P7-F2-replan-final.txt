1. 最终判断。
在现有批准需求、六文件边界及安全硬约束内，没有证据支持一个可以交付 F2 的最小实施范围。F2/f2 继续 blocked，不直接派 f3，也不把原六文件包换名重派。
本文引用的 Q1、Q2、R 分别是同目录 P7-F2-Q1.txt、P7-F2-Q2.txt、P7-F2-replan.txt，冒号后为报告行号；产品基点仍为 /tmp/bot-wt/P7-F2-replan 的 ed336c9a39660a30f23f415debc9e07f22b026ea，不引入其他分支成果。
Q2:13–24、44–46 已否定 R:46 的必要前提：没有找到可信的管理四档及 ceiling 输入，renderer 常量桩和 shell tiers 不能顶替。该停止条件现已触发，R:41–68 的条件实施及验收包不再可派发。

2. 两条路线的最终取舍。
路线 A 是继续 authority 的文本修复，或只做合成管理工具的原生审批演示；两者都可能局部有用，但不能交付当前 F2。前者没有真正 handoff 出口，后者没有可信分层与真实 main 消费者，不能通过换验收名称解除阻塞（R:15–19、27–32；Q1:55–58）。
路线 B 是冻结 F2，承认缺失的是宿主权威策略和真实执行接缝，待主会话明确批准相应架构范围后再重排前置任务。选择 B，因为继续 A 会把“测试计数成功”误记为“安全管理可用”，同时耗尽修复预算却不消除缺口（Q1:56、62；Q2:46、62）。
REDUCE 在这里减少继续投入和不成立的交付承诺，不删除 Alice 改名、install X/disable Y 正常成功要求，也不把全部拒绝、空动作表或永久 pending 算成功（R:9、62–66）。

3. 已成立的复用结论必须保留。
原生 dsh pipeline/user-approval 能承接 ask、allowed-once 与同次调用继续执行；现有 Peer/eventId 台账和审批卡可以复用，无需再造审批器或授权数据库（Q1:18–32、61）。
已装 experimental-auto-review 确有 ctx.llm.stream 的真实审核实现；不能写成“上游没有审核服务”。但它按 session Auto preset 工作，Auto 绑定 danger-full-access，不是管理四档或 ceiling 服务；本仓可安全复用的管理级挂载仍未证实，不能直接开启（Q2:27–38）。
人工 ask 可以是已有能力的回退机制，但在缺少可信策略决定何时允许回退的情况下，不能以“一律人工审批”替换四档，尤其不能让 blocked 经批准放行（Q2:15–22、41–50）。

4. 冻结点不止一个，不能只补配置后放行。
第一，批准关联还不是执行快照保证。arguments 值冻结不阻止 exec 外壳、工具名、Agent 或同名 handler 在内部被替换；必须有批准内容与最终执行内容的一致性边界及替换反例，而不是只比 callId（Q1:35–38）。
第二，网关存在但无 answer client 时会保留 pending；现有无 renderer deadline 不覆盖有 renderer 一直不答。无人作答不执行，不等于已经证明有界终结；桥的 timeout/outcome unknown 也不等于副作用为零（Q1:40–46）。
第三，当前 SDK admin 工具与 main 桥没有生产接线。六文件内挂合成工具可以探索机制，但不证明真实管理动作闭环；真实订阅启动或协议变动已经触及原停止边界（Q1:49–58）。
第四，既有 shell-ask 顺序和 plugin_manager 硬禁仍有效，不能靠 YAML 顺序、改工具名或旁路 guard 解决（Q1:53–54；Q2:47–49）。

5. 下一步真正需要的范围与决策，仅供主会话承接。
需要先批准“前置架构范围”，而非批准下一轮字符串修复。范围至少包含可信策略输入的所有者与接入边界、同次批准到最终执行的绑定边界、无人作答的取消/期限生命周期，以及真实 SDK→main 消费者启动位置；这些都不是原六文件包已经具备的能力（Q1:37–46、55–62；Q2:13–24）。
策略决策必须明确权威数据由哪个宿主组件提供，以及四档与 ceiling 如何从可信输入进入执行链。当前没有可指定为现成服务的证据；在不批准扩大集成范围之前，这一前置保持 blocked，不能临时造配置常量、模型字段或第二授权存储（Q2:19–24、44–46）。
审核决策必须区分“保留真 auto_review 子项 blocked”与“扩大范围改造已装审核插件以适配非 DFA 的管理粒度”。后者目前没有可直接复用的 exported review API，必须另行确定改造边界与复用成本，不能本报告自行批准，也不能用启用 Auto 代替（Q2:29–38、49）。
执行接线决策必须允许主会话重新划定真实消费者、批准快照复核和终结生命周期的文件/契约边界；若涉及协议契约，应按用户 C2 接口确认处理。确认范围不等于批准实施，更不等于允许削弱安全默认（Q1:38、43–46、57）。
上述是已知缺口的范围决策，不是再派 Q1/Q2 同题调研的理由；现有证据足以冻结。也不重新询问原版已经确定的四档行为，不提出自然语言授权平台、新 Mandate 格式或数据库（Q1:63；Q2:61–62；R:31、71）。
只有前置有了具体可信输入、真实执行路径和可证伪边界，才有资格重新拆任务、确定白名单和验收；届时仍须保留正常成功、跨调用批准隔离与替换/取消红例，不能沿用本报告宣布 ready（R:62–73；Q1:62）。
