一、失败探针详情
1. 指令文件反向软链逃逸，真实 Loader（不是仅模拟 fs.resolve）
   在主 bot 工作区写 innocent.md='innocent'，造 CLAUDE.local.md -> innocent.md。worker 在已有脚本中先 read CLAUDE.local.md 满足上游 read-before-edit，再 edit CLAUDE.local.md，把 innocent 改为 injected-instruction。
   实际 tool/result isError=false，宿主 innocent.md 字节变为 injected-instruction。CLAUDE.local.md 本身仍指向该文件，指令内容因此已修改。
   根因：instructionFileDenial 在 resolvedPath 存在时完全舍弃 rawPath；只判断最终 target basename。正向 link.md→AGENTS.md 已拦，反向 AGENTS/CLAUDE 名→普通文件却放行。
   证据 E/inverse-symlink.test.ts（从申报 e2e 导出，改动仅证据副本），生成器 E/prepare-probes.py；日志明确保留工具结果及实际内容。

2. 同文件并发窗口
   用真实 registerCreateBot、Slots、真实身份读取；仅把 main 请求响应延迟。两个 definition.execute 并发，artifacts 都为 ['shared.txt']。在 main 响应任何一个之前，两次请求均已进入 channel。回应 w0、w1 后两个 Promise 都 fulfilled，均拿到 sessionId。
   根因：create.mjs:134-138 查冲突；直到 await channel.request 返回后的 :169 才 registerClaims。pending create 没有声明占位，所以同一时间窗口互相看不见。
   这不是「未声明 advisory 档」的已知上限：本探针两边都显式声明相同文件，仍然双双通过。

3. subdir 软链引出主 bot 工作区
   真实临时目录 workspaces/main、workspaces/other；main/out 软链指向 other。真实 BotsMetaStore + createWorkerBot，请求 subdir='out'，RPC 只模拟 session/list/create/rename 并记录参数。
   实际 result.ok=true，session/create 恰一次，传入的 cwd 经过 realpath 后是 workspaces/other。证明 main 编排已接受主 bot 子树外工作区；本项没有伪称完成了恶意 worker 的真实 Loader 写入，证据边界是「实际调用了创建接口并授予错误 cwd」。
   根因：orchestrate.ts:415-418 join + recursive mkdir 会接受已有目录软链，未 canonicalize 后再核对属于 main cwd。布局父路径检查也仅是词面，但本探针只针对这次新增 subdir 面。

二、advisory 精确语义
   create.mjs:207 只有 subdir===undefined && artifacts===undefined 才返回 advisory。subdir 已传但未声明文件、或 artifacts=[]，没有写入责任也不会警告。claims 是声明级而非文件写强制级，不检查 worker 实际写到的其他文件；turn/end 释放；不持久化，不恢复跨重启声明。这些限制不得描述为强制文件所有权。本次主要 FAIL 是显式相同声明的 pending-create 竞态，不据此扩写未授权功能。
