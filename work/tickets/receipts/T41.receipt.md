## 5. dead-entries 段②红：已实证的机制与未明的触发（请经理定夺）

**机制（全部实测，插桩已还原）**：
1. 段①结束时 `localStorage['pbots.shim.hidden-agents']` 仍为 null、renderer coordinator 无任何 hide 帧（requests 全量核过）。
2. 段②第一次 reset reload 后约 24s，**上游经 coordinator 协议发来 `setAgentHiddenFromSidebar(botId, isHidden:true)`**——shim case 执行（coordinator 侧日志实证）、writeHidden 写入 localStorage（栈实证：MessagePort → handleRequest → deps.setAgentHidden → writeHidden）。
3. 后果：raw 带 isHiddenFromSidebar=true → 上游 visibleAgents 滤空 → 侧栏 rows:[] → reset 的 `.sand-agent-item hasText 'P5-52 probe'` 60s 等不到。

**已排除**：
- 静置实验（就绪/静置 35s/reload+35s，零操作）：ls 恒 null——**不操作不触发**。
- 右键行菜单（7 项含 Hide）+ Escape + reload：ls 恒 null——**菜单本身与 Escape 不触发**。
- Account/Settings/Search palette/info pane 打开关闭 + reload：ls 恒 null（复刻实验绿）。
- 刀 B（不读 localStorage）曾 1 绿 1 红——后证实那次「绿」build 产物与源不一致，不可靠；后续刀 A 3/3 + 完整 5/5 的对照才作数。

**未定位**：上游发出 hide 帧的确切 UI 路径。0.18 树 grep `setAgentHiddenFromSidebar` 的调用点只有行菜单 onHide 与 Hidden Bots 对话框 unhide（ProductionRenderer:3053-3065），**没有发现自动路径**；帧发送方栈在 MessagePort 异步边界断（postMessage 语义），无法直接拿到 0.18 侧调用栈。触发条件为「段①操作组合 + reload + raw 带 isHidden 键」三者共同必要——怀疑段①某操作（消息悬浮菜单/右键菜单/settings/palette/pane 的组合序列）让 0.18 上游留下 pending 状态，reload 后恢复时误发。

**影响面评估**：生产用户真实操作（Hide/Unhide/重启）按 §4 各实验均正常；此问题只在「dead-entries 段①的特定操作序列」下出现。但**若根因是 0.18 上游的自动 hide 路径，用户侧存在 bot 被意外隐藏的风险**——建议 T41b 追根因（在 0.18 coordinator-client 的 call('setAgentHiddenFromSidebar') 处 patch 栈日志，或逐操作二分段①），不建议裁豁免了事。
