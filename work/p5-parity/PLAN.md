## 2. 通用约定（全部任务适用）
- **测试**：fake LLM 驱动工具调用（`app/sdk/tests/support/fake/plugin.mjs`）；SDK 侧 launcher 复用 `app/sdk/tests/support/runtime.ts`；UI 侧 playwright `_electron`，重启只用 `electronApp.close()` 再 launch。L-UI 用 `HOME=/tmp/bot-p5-<id>`；L-AP 沙箱类用决策 8 的路径。
- **正对照**（B §6）：凡「看不见 / 写不进 / 连不上」断言，同一探针先在 stock profile（不配 `runnerCommand`、不挂 guard）下跑并命中，断言看 errno（EROFS / ENOENT / ECONNREFUSED / ENETUNREACH / EAI_*），不只看「文件不存在」。探针只做存在性 / 连通性检查，不读真实凭证内容。
- **断言口径**（沿用 p4-ui PLAN §2 +4）：精确值或显式枚举集合，不用否定比较；「没有出卡」= `approval/asked` 计数 === 0；「dsh 没收到」= main 侧 `/api` 计数 === 0。
- **进程**（CLAUDE.md §5）：测试只在 teardown 里结束自己 spawn 的子进程；agent shell 不手工 kill，不用 pkill / killall / -P。
- **合并**：每次合入 main 后跑所在包全量（app/sdk → `pnpm -C app/sdk test`；app/ui → build + 单测 + e2e），绿了才算合并完成（LEARNINGS 2026-11-02）。evidence 只放报告、脚本、frames，运行时目录（handoff、runtime、lock）用后即删（LEARNINGS 2026-11-03）。
- **报告位置**：VERIFY / evidence 一律写主仓 `/home/lingxufeng/bot/work/p5-parity/…`，不写 worktree 内的 `work/`。

### D-1 受控升权路径（W1-AP，影响 P5-22、Q-013 第 2 行）
**题干**：bash 和文件工具今天的升权只有一档 `danger-full-access`（`D/sandbox/sandbox/src/escalation.ts:30-31`：workspace-write 只能升到它），而这一档直接跳过 confine，`runnerCommand` wrapper 根本不执行（`D/sandbox/bash-sandbox/src/index.ts:92-100`）。P5-04 先把它整体拒绝。我们需要一条「放开联网，或多放开一个写目录，但凭证遮蔽（P5-01 清单）始终保留」的路径。**约束**：① pre-execute 只能返回 allow / deny / cancel / ask，不能改写参数或换执行器（`D/core/tools/src/contracts.ts:358-361`）；② 上游沙箱接口明确不表达网络维度（`D/sandbox/sandbox/src/index.ts:24-59`，R5 §②）；③ wrapper 收到的只有 argv 和 shell-env 构造的环境（R5 §④ 键表：有 `DSH_SESSION_ID`，没有 callId）。验收统一为 B A4 升权格：批准升权后仍读不到任何哨兵。
**选项**：
- ① **我们的插件注册一个受控执行工具**（如 `bash_elevated {command, network?:bool, write_dir?:string}`），执行时复用同一个 wrapper，按批准内容去掉 `--unshare-net` 或多 `--bind` 一个目录，遮蔽清单不变；该工具每次 ASK、无始终允许；`danger-full-access` 继续由 P5-04 拒绝。代价：模型可见的新工具（工具描述、snapshot），要引导模型在需要联网时改用它；要自己实现执行（复用上游 shell 执行服务的程度待 builder 查）。
- ② **wrapper 读一次性许可**：pre-execute 对某种升权请求出卡，批准后由 main 签发一次性许可文件（放遮蔽目录里，按 `DSH_SESSION_ID` + 序号，用后即删），wrapper 读到就去掉 `--unshare-net`。代价：受约束 ①，模型无法用现有参数表达「要联网」而又不触发 `danger-full-access`；同会话并发 bash 会抢同一张许可；许可文件本身成为需要遮蔽的新凭证。
- ③ **不做**：本 slug 内联网和写工作目录外一直不可用（P5-04 的拒绝永久保留），Q-013 第 2 行写明；需要时另开 slug。代价：`pip install`、`git clone` 之类必须由用户在 bot 外手动做（B §4 死因 3）。
- ④ **向上游提 issue / PR**：给沙箱策略加网络维度、让升权保留 confine（搬运阶梯第 1 级的长期解）；本 slug 内按 ③ 过渡。代价：时间不可控；需 scout 先查上游是否已有相关 issue / 计划。

### D-2 MCP 元数据桥（W1-AP，影响 P5-23、P5-24 的稳定身份、Q-013 第 7–9 行）
**题干**：B §7 第 7–9 行要按连接器工具的 `readOnlyHint` / `destructiveHint` 分档，授权键要用稳定身份 `(serverName, rawName)`。但 dsh mcp-client 注册的工具定义不带 annotations，pre-execute 的 exec 上也没有可信的 MCP 身份字段（`D/mcp/mcp-client/src/tools.ts:131-150,229-246`，已装产物 `N/@deepseek-ai+dsh-mcp-client@0.2.2-alpha.2_*/…/lib/index.js:127-153,179-197` 一致）；工具名 `mcp__<server>__<raw>` 经归一化并可能带 hash，不能反拆（R4 §3）。
**scout 先查（结果写 `reuse/d2-mcp-meta.md`）**：(a) 上游 deepseek-harness 当前 main 及 issue / PR 里是否已有或计划提供工具 annotations / 来源元数据给策略层（搜 `annotations`、`readOnlyHint`、`toolSource`）；(b) mcp-client 是否有可从插件侧 `ctx.get` 拿到的服务，能按已注册工具名查回原始 MCP tool 对象；(c) 名字归一化函数是否从包入口导出（若导出，main 可从 `(serverName, rawName)` 正向算出 toolName 做精确匹配）。
**选项**：
