## 3. e2e 真状态链（验收 3）


链路设计（逐档轮询、不靠固定 sleep）：
- **waiting（稳定态）**：worker W1 挂审批（peer deliver + toolCall）→ rank0 → 断 `工作状态-原地踱步张望.webm` + readyState≥2 + 截图；
- **批准**：rt 侧 `$events` 流抓审批 eventId（T40 旁证同法）→ 同流连接 `$events/result` 后台批准——不开 W1 会话（打开会清未读）；
- **success**：W2（纯 textCall，p6-workers Researcher 同款——**实测审批链完成不产生未读**，故 success 档走第二个 worker）完成未读 → rank3 → **原子单帧捕获**（同一次 evaluate 读 state+src+ready，雀跃动画仅 ~1-2s 分两次读会漏）→ 截图；
- **idle（M1）**：success 一次动画 ended → idle，序列断言 `/success.*idle/`；
- **点宠物窗 → 主窗获焦**：Xvfb 下 `app.evaluate` 断主窗 `isFocused()===true`（工单给的两种里选了 isFocused——p6-notify 的 blur 测试证明 Xvfb 焦点语义可用，无需另加计数面）；
- **thinking/working/error**：main 驱动 + expectState（data-state + currentSrc 文件名 + readyState≥2）逐档截图；**真回合的瞬时中间态（thinking/working）只记录不锁动画**（溜走的态 currentSrc 断言注定超时，动画断言由 main 驱动段覆盖——回执写明此取舍）。

回归（同命令批）：`p6-notify + p6-workers → 3 passed (32.4s)`。

## 8. 风险与存疑

- **审批链完成不产生未读**（实测 chunkCount=1、endReason=completed、归 Done 无 Unread 徽标）——与 p6-workers「Researcher 纯 text 完成即未读」不同。原因未深挖（可能 fake 审批回合的完成路径不同）；对本单无影响（success 档已走 W2），但**值得记 LEARNINGS**：worker 完成未读依赖 `api-session/status` 的 running 真跳变（emit(W,true)→emit(W,false)），审批挂起期间的 running 状态序列可能不同。
- 过程事故：清诊断插桩的 regex 切坏 spec（语法红）——发现于 V7 前跑、立即修复提交；两把假绿变异（T41b 同款教训：**e2e 变异必须 rebuild**）。
