## 1. 核心旅程

1. 用户问一个需要推理的问题 → 模型先吐 reasoning-delta。**现状卡点**：`start` 帧把 `streaming` 置 `{text:''}`，推理阶段会出现一个**空的流式气泡**（DeepSeek reasoner 下是常态）。解法：推理阶段不渲染空气泡，改渲染一条 live thinking 行（§2.2），正文第一个 text-delta 到达才出流式气泡。
2. 回答定稿 → 气泡上方留一条收起的「思考」行，预览首行；想看就点开，不想看它只占 34px。
3. 用户切去别的 bot 干活，这边 bot 回复了（侧栏未读点亮，已有）。
4. **最容易卡住的一步**：切回来，看到一屏文字不知道从哪读起。解法：未读线钉在第一条新内容前，且进入时若新内容超过一屏，视口滚到未读线（而不是底部）。
5. 隔天打开同一个 bot → 顶部与跨日处有「昨天 14:05 / 今天 09:12」，知道上下文是何时的。

## 3. B14 时间分隔行

- 规则（照抄 E78 `vmt`）：遍历带 `at` 的 item，`prev===null || |at-prev| >= 900_000 || !sameLocalDay(at,prev)` → 在该 item 前插一行；`at===null` 的 item 跳过且不更新 prev。thinking 行与其气泡同一事件同一 `at`，分隔行落在 thinking 行之前。
- 文案（E78 `UR`，zh-CN）：今天 `今天 14:05`；昨天 `昨天 14:05`；同年 `11月3日周二 14:05`；跨年 `2025年11月3日 14:05`。用 `Intl.DateTimeFormat('zh-CN', …)`，`now` 作参数注入（可测）。
- 派生于渲染：`withMarkers(items, now, dividerBeforeId)` 纯函数返回 items + 分隔/未读行，放 reduce.ts 旁（单测直接测），不进 store。
- 「加载更早」prepend 后整体重算，顶部分隔行跟着上移，无需特判。
- 长回合（工具跑 >15min）中间也会出分隔行——保留，等同 0.78.1，对长任务是有用信息。

## 4. 未读线

- 状态（store，前端派生，不持久化）：`readMark: Record<sid, number>`。
- **离开**一个 bot（`select` 换走时）：`readMark[prev] = 该 view 最新 item 的 at`。
- **进入**时冻结：`dividerBefore[sid] = 第一个 at > readMark[sid] 且 kind !== 'user' 的 item id`，否则 null。冻结的是 id，所以本次停留期间 live 新到的消息不会让线跳动，也不会凭空长出第二条。恰 1 条由「至多一个 id」保证。
- 无 readMark（本次启动首次进入 / 重启后）→ 不出线。持久化跳过：重启后未读线要靠后端已读游标，等有需求再做。
- 消失：线在本次停留内一直在（不随滚动消失——会消失的线让人找不到读到哪），下次离开时随 readMark 更新而消失。
- 进入滚动：有线且「线以下内容高 > 视口高」→ 线滚到视口顶下 28px（chat-col 上内边距）；否则维持现有贴底。新消息胶囊逻辑不动。
- 与分隔行同处：顺序为 未读线 → 时间分隔行 → item（E78 `Emt` 先 push divider 再 splice timestamp）。
- 文案：「新消息」（0.78.1 可见文案只有 `New`，不带计数，E78 `isRobC`；aria-label「以下为新消息」）。

## 7. 反提案

**不要把推理文本做成助手气泡里的灰色斜体引用块 / 默认展开**（ChatGPT、DeepSeek 网页的默认做法，大家顺手就会照做）。理由：① 它和工具行是同一类「过程信息」，0.18/0.78.1 都把它放进 outline 行族，混进气泡会破坏「气泡 = 结论，行 = 过程」的层级；② 默认展开在流式期间会把正文往下推、触发贴底滚动抖动，推理常比答案长数倍；③ 气泡复制 / Markdown 渲染会把推理混进去。始终收起、独立成行。

**也不要把未读线做成「滚过就淡出」**：Slack 式持久线才能回答「我读到哪了」，淡出版本在用户第一次滚动后就丢掉了唯一的定位信息。
