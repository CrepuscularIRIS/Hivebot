## 0. 主张（先行）

**「独立会话头 vs 38px 合并」是假二选一。原版本来就是合并的，只是那一行高 52。**
证据链：0.18 `.sand-cover-drag` 是 `position:fixed; top:0; height:52px` 的拖拽罩（window-chrome/view.css:3-10），会话头 `min-height:51px + border-bottom 1px` = **52**，恰好被这层罩盖住——会话头就是顶行，上面没有另一条 titlebar。0.78.1 linux/win 走 `shellWindowControls` 档，`--sand-titlebar-block` = **52**（078-values 结论4）。38 只是 fallback。
所以推荐：**不叠两行（38 titlebar + 51 头 = 89px 死高度，原版没有这种形态），而是把现有合并行从 38 抬到 52，内容换成原版 identity 结构。** PAB R0 的「合并」保留，推翻的只是「38」这个数。

## 4. 迁移风险与处置

1. **`--sand-titlebar-block` 是共享 token**（sidebar-head、pane-head、titlebar 都吃）。推荐**改 token 值 38→52**（`sand-tokens.css:1159`），三处顶行一起变 52，整窗顶带对齐成一条线——这正是原版效果。只改 chat-header 而侧栏留 38 会出现 14px 台阶，比现状更差。
2. **WCO 高必须同步**：`window.ts:12-13` `titleBarOverlay.height 38→52`，否则原生窗口钮贴在 52 行的上 38，垂直不居中。这两处**超出 PLAN 文件栏**（只列 App.tsx / chat-header.css / spec），需主会话追认（一行改动各一处）。若不追认，方案 S 不成立，宁可 GU 判 waived（方案 K），不要上半成品。
3. 视觉 e2e：`visual.spec.ts` 无 38 硬编码断言（已 grep：只断 pane-head padding、无品牌位），新增 `visual-header.spec.ts` 断：header `getBoundingClientRect().height ≥ 51`、identity 内有 `.avatar` 28px、点 identity 后 pane 出现、`border-bottom-width=1px`、亮暗各一次取 border/working 计算色。
4. Market 页（`App.tsx:77`）不渲染会话头，但其顶部同样吃 token；078-values D2 Back 钮容器高 48、左 padding 48——变 52 后检查 Back 与 WCO 不重叠即可，不改。
5. 回滚面：token 值 + WCO 高 + JSX 一段，单 commit 可回退，符合验收③ waived 路径。

## 5. 反提案：不要做「38 titlebar + 51 独立头」两层

R8/AUD 的字面「独立 ≥51px 会话头」最容易被读成在 38 拖拽条下面再加一行。不要这样：①原版没有这种形态（拖拽罩 52 盖在会话头上，二者是同一行）；②纵向白丢 37px，聊天列本就 min 424 宽、窗口默认 820 高；③两条水平线（titlebar 底 + header 底）让顶部显得像网页后台；④WCO 只能对齐其中一行，另一行必然失衡。
