理由（≤5 行）:
1. MVP 第一条（每个 bot 有自己的 agent 配置）在 0.78.1 renderer 里不存在。走 A 就必须改闭源 minify bundle，「保留外形」的收益从第一步就开始流失（ARCH:8、:102）。
2. A 的适配层要在两套外来协议之间翻译，属于自建，没有上游，没有 sourcemap，启动面也没测过。B 可以直接搬 dsh 在维护的 React client 包（第 1/2 级），与「搬运工优先」一致。
3. B 的视觉保真靠 RE-ui-shell 的可提取资产（66 个资产、字体、图标连字、CSS、3,880 条 en 文案）加组件树来保证，MVP 只有 4 页，范围有界。

最担心的风险: B 的范围膨胀成「重写 75 个 lazy entrypoint」，或者 dsh client 包与 Grok 的视觉结构冲突太大，最后两边都不像。缓解办法：P4 只做 RE-ui-shell §1.4 的 4 页 + 审批卡 + tool-call 行；先派 scout 核实 dsh client 包能否脱离 Cordis 浏览器壳组合，不行就退回到「自写 React + 只搬资产」。

reverse_take: 最可能的失败方式是 A 卡在登录墙或启动期未知调用上，per-bot 配置又不得不去改 minify 代码，最后变成「逆向 + 自建」两头都付钱。更笨也更稳的做法是 B′：拿 dsh 自带的 React client 包当骨架，套上 Grok 的字体、图标、CSS，只做 4 个 MVP 页。
