## 结论先行（MATRIX.md 全表）

**用户说的「错位一系列」实锤为窗口层问题，不是页面布局**：Windows 侧窗口外框 **1296×760**（screenX=−8），屏幕 1280×800/可用高 752——左右各 8px 溢出屏外、底部压任务栏 8px。页面 CSS 两平台同参渲染**完全一致**（对齐视口 1280×752 后全部选择器几何 Δ≤1.5px、dpr 均 1）。候选原因类：**平台分支样式**——win32 frameless 最大化未剥 8px resize 边框（Electron frame:false 窗口 maximize 系统保留边框边距）；修法待 REA 对照原版 0.78.1 的 win32 标题栏/窗口分支（派工单第 6 面，在途）。
次级：两处字体度量微差（市场标题 −7.3px、onboarding 行 +3px）——Segoe UI vs Linux 默认的同参渲染差，量级小不构成错位。

## 坑与记档

- CDP `Page.screenshot` 在 Windows 侧把**窗口外屏幕内容**带进截图（captureBeyondViewport）——pair 图上的桌面条/系统控件/暗带即窗口溢出屏的直接视觉证据，恰好佐证根因；做像素对比时别把这些当页面元素。
- `Browser.getWindowForTarget` 在 playwright connectOverCDP 的 page/browser session 均缺（`wasn't found`）——窗口尺寸操作用 `setViewportSize`（Emulation 域）替代。
- 截图 `clip` 参数在该 Windows 实例上未生效（04-titlebar 仍全窗）——取证未受影响（几何走 evaluate）。
