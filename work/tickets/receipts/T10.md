### ③c 疑点定位（供后续单引用）
**防线是上游 helper profile 的 `--tmpfs /tmp`，不是 wrapper，也不是 guard 远端根。** dsh-sandbox-local `lib/index.js:34-35`：`policy.mode === 'workspace-write'` 时 profile 加 `--tmpfs /tmp`。测试的宿主哨兵 HOME（`TEST_ROOT = mkdtemp(tmpdir())`）和远端夹具（`ssh-host.ts:82` `tmkdir` → `os.tmpdir()`）都在 /tmp 下，于是原版 helper 沙箱也看不见。HEAD~1 能先红，是因为 mode 丢失落在 read-only 档（不加 tmpfs /tmp）。mode 补丁把档位拉回 workspace-write，同时把 ④a/④b 变成了空测。

结论：wrapper 必要性**不受损**——真实部署 HOME 在 /home/<user>，不在 /tmp，原版 helper 照读（/var/tmp 列即模拟）。不收窄单子；要改的是探针位置（T10b）。

### 三处裁决
1. **③c**：见上。T10 产品代码成立；测试在标准跑法下对「删 wrapper」不敏感 → 验收 2（④d 两刀）在默认环境不成立 → 不通过，T10b 把夹具挪出 /tmp 并加前提断言。
2. **③a 形态偏离：不接受。** 偏离理由「bash 直写在 read-only 被挡」是 mode 补丁前的现象；经理探针把 ③a 第一个调用改成 bash `printf %s '<mark>' > mark.txt`，在 HEAD 下两种 TMPDIR 都绿、文件内容 = mark。直写形态才证明 wrapper 保留了 profile 的 `--bind <ws>` 写通路（读回形态靠 `--ro-bind / /` 也能过）→ T10b 恢复 DESIGN 形态并显式断言 0 卡。
3. **mode 补丁：合法，保留。** 与 base 行逐字相同（dsh-base `cordis.patch.yml:246` `mode: !!js process.env.DSH_PERMISSION_MODE ?? 'workspace-write'`），由同一加载器在 dsh 子进程求值。`!!js` 是常量字面表达式，不插任何运行时值，和 T9ae 的 yamlScalar 原则（运行时路径/字符串必须引号化）不冲突；值域由 sandbox-policy schema 校验。删掉它 ③a 红，已有格守着。修的是 T9a 起就存在的 ssh 会话只读 bug（同 id 覆盖整键替换），在 start.ts 边界内。
