## 0. 立场与证据边界
- **推荐「原版外形、收窄功能」，不做 dsh 风格工作台。** 同一窗口始终是 roster + 会话，不另设 bot 卡片总览。
- `01-boot.png` 只有未登录封面：可证明近黑底、克制白字、留白和窗口控制；**不能声称它证明了登录后布局**。
- 登录后逐区块依据 `RE-ui-shell.md` §3；颜色、尺寸依据 `RE-theme.md`；其余交互均为本提案，不冒称原版行为。
- 用户最新「尽量一致」优先于 BRIEF 旧版「不追求像素一致」：已知常量尽量照搬，未知细节不凭空宣称还原。
- 比较三条路：保留 dsh 外观最快但不合视觉目标；复制原版整壳超范围；**采用既定 dsh 骨架 + Grok theme/产品 slot**，不增组件库。

## 1. P-A · bot 列表 / 侧栏与最小新建对话框

### 布局与信息层级
- 标题栏高 38px，使用 chrome 背景；不要把封面的巨大 wordmark 移进日常侧栏。
- 侧栏默认 280px，宽度调整限定 240–400px；条目圆角 12px，中性 hover/active，头像与名称为主。
- 顶部紧凑 Grok 品牌与「新建 Bot」；对应原版 Header，**不沿用「New chat」**，避免误认一个 bot 可开多会话。
- 中部唯一纵向 bot 列表：主 bot 固定首位，轻量「主 Bot」标记；其余稳定排列，不随每个 chunk 重排。
- 每项只保留头像、截断名称、运行角标；完整名称由 tooltip 提供，配置不塞进列表第二行。
- 底部保留市场入口；删去原版账号脚部，不拿假头像、Sign in 或账号菜单补空。
- 右侧仍是选中 bot 的 P-B；P-A 不额外占据一个「管理 bot」主页面。
- 最重要的一件事是「当前在哪个 bot」；选中底色与键盘 focus 分开，运行点不能替代选中态。
- 新建为居中单步对话框，建议宽 420px，最大为窗口宽减 32px；沿用原版浮层色、描边与圆角体系。

```text
┌──────────────────── titlebar 38 ────────────────────┐
│ Grok Bot      [+ 新建] │ 选中 Bot                    │
│                       │                            │
│ [头像] 主 Bot    [主] │          会话 P-B           │
│ [头像] Bot A       ○ │                            │
│ [头像] Bot B         │                            │
│                       │                            │
│ [市场]                │ [composer]                 │
└───────────────────────┴────────────────────────────┘
                  ┌─ 新建 Bot ───────────────┐
                  │ Agent preset [默认   v] │
                  │ 模型         [当前   v] │
                  │ 配置随 bot 固定，       │
                  │ 换配置需新建            │
                  │        [取消] [创建]    │
                  └─────────────────────────┘
```

### 核心旅程与交互
- 打开 → 恢复列表/主 bot → 新建 → 选 agent preset、模型 → 创建 → 自动选中 → composer 获得焦点。
- 最容易卡住的是 **「preset 是什么、能否后改」**：标为「Agent preset（能力配置）」，旁注明固定规则；不混入 permission preset。
- 候选来自 #1/#2；初始化遵循真实默认项，无有效候选则禁创建并显示原因，不虚构一个可用模型。
- 创建按钮立即进入进行态，防双击；成功前不把猜测的 bot 插进列表，不添加本次未要求的名称字段。
- #3/#4 创建后由 #5 设模型；若模型设置失败，明确「Bot 已创建，模型未切换」，进入真实 bot，**不让再次点创建造成副本**。
- 切换 bot 不打断后台流；只切选中 session scope，草稿按 bot 隔离，不能把 A 的草稿带到 B。
- 对话框 trap focus；Esc/背景关闭仅在非提交态生效；关闭后焦点回新建按钮。禁用项旁写原因，不只变灰。

### 状态清单
- **空**：启动时主 bot 缺失按既定流程自动创建；恢复前不闪「还没有 Bot」。失败后显示「主 Bot 初始化失败」与明确重试。
- **加载**：保留侧栏轮廓与少量条目骨架；已恢复的列表不因局部请求重新整屏清空。
- **流式/长任务**：`SessionSummary.running` 驱动角标；不显示无来源百分比，不用侧栏逐字预览制造跳动。
- **审批挂起**：保持当前页面与列表位置；审批行动放 P-B，不抢焦点、不自动跳转到另一个 bot。
- **失败**：候选加载失败在表单字段处重试；创建失败保留选择，列表不出现失败「幽灵 bot」。
- **离线**：显示「本地服务连接中断」，保留已读列表与历史；禁新建，勿写成「检查互联网」。
- **只读降级**：失效 bot 仍可选、可读历史；角标附文字说明，不从列表隐藏，不循环自动重试。

## 2. P-B · 会话流、工具行与审批卡

### 布局与信息层级
- 对应原版 ChatHeader → Transcript → Composer 三段，右侧 info-pane 不留空槽；不增加常驻工具控制台。
- Header 以 bot 名为主，preset/连接器为弱化只读配置；P-D 接入后承载「用此配置新建」，本轮不伪造编辑入口。
- transcript 沿用 `min(640px,100%)` 气泡上限、14px/22px 正文和原版对侧缩进；用户右、assistant 左。
- 工具是**紧凑步骤行而非大卡片**：loading / wrench / x-circle + 工具名与可得的参数摘要；详情按需展开。
- 审批是工具行下唯一需要突出的卡：先说明「要执行什么」，再显示理由与两项动作；不整块警告色铺满。
- composer 固定底部，保持原版输入容器形态；仅呈现实际可工作的文本发送、模型选择与打断，不露附件/语音假入口。

```text
┌─ Bot A ────────────────────────────────────────────┐
│ preset（只读） · 连接器（只读）                     │
├────────────────────────────────────────────────────┤
│                             [用户消息]             │
│ [assistant 流式正文……]                            │
│ loading  Bash · 参数摘要                       [v] │
│ ┌─ 需要批准 ─────────────────────────────────────┐ │
│ │ 工具名 / 完整命令或参数 / 可得的执行理由        │ │
│ │                         [拒绝] [仅批准这一次]  │ │
│ └────────────────────────────────────────────────┘ │
│ [后续消息或工具结果]                               │
│                          [回到最新消息]（需要时） │
├────────────────────────────────────────────────────┤
│ [输入消息……                           ] [发送/停止]│
└────────────────────────────────────────────────────┘
```

### 核心旅程与交互
- 发送 → receipt → 首个 chunk → 工具行 → 审批 → 结果 → 定稿；正文是主线，参数与协议信息为次级。
- **最易卡住是「已批准是否等于已执行」**：提交后写「正在提交决定」，决策确认后写「已批准，等待工具结果」；tool/result 才决定执行成功。
- 流式节点稳定更新，assistant/message 到达后原位替换，不追加第二份答案；首块前只显示轻量生成态。
- 阅读旧消息时不强制跟底；只有本已在底部才随流滚动。出现新内容提供「回到最新消息」，审批也不强拉滚动。
- Enter 发送、Shift+Enter 换行；中文输入法组合态不发送；流式时主动作是「停止」，打断待确认期间防重复点击。
- 工具参数按文本/代码显示，不执行 HTML；长命令可折叠，但批准前可查看完整内容，未知工具使用 generic fallback。
- 审批只按真实 `agentId` 归属、按 `callId` 关联；缺 callId 时放该 bot 流内独立审批块，不挂到「最近一行」猜测关联。
- 活跃按钮只来自 `$events` 未决请求；`approval/asked` 历史记录不能生成可点击批准按钮。
- `ready` 后补发沿上游关联更新，不重复卡；作答必须绑定当前 clientId/eventId，不能复用断线前闭包。
- 两按钮同等清晰，批准标为「仅批准这一次」；不设默认 Enter 批准，不出现「始终允许」或权限档位切换。

### 状态清单
- **空**：选中 bot 后简短「向这个 Bot 发送第一条消息」，不堆模板建议或封面营销文案。
- **加载**：初开加载历史；取更早记录用顶部局部指示，失败只重试该页，保持滚动锚点。
- **流式/长任务**：已有文字持续可读；工具等待与模型生成分开标识，不把静默间隔直接判失败。
- **审批挂起**：行标「等待批准」，卡内显示可得理由；不展示虚构倒计时——main deadline 不是所有在线 pending 的通用超时。
- **失败**：发送失败保留草稿；同一发送重试沿用 requestId。审批传输结果不确定时先同步，不能直接恢复「批准」诱导盲重答。
- **离线**：保留历史/草稿与已收到片段，禁发送、批准和停止等依赖连接的动作；片段注明未确认完成，不能冒充定稿。
- **只读降级**：常驻「连接器已失效，请新建 bot」；禁发送与失效会话的执行动作，历史照读，不先发一次失败消息试探。
- **终态**：cancel 移除交互按钮；审计有据时显示「已取消/已拒绝/不可用」。main 代答 rejected 只显示「已拒绝」，无来源不声称「用户拒绝」或「已超时」。
- **打断**：以真实 turn/end interrupted 收敛；保留部分文本并标已停止，不把点击停止瞬间当成停止成功。
- 可访问性：按钮有可读名称；工具展开用 disclosure；播报状态变化而非每个 chunk；减少动态效果时关闭非必要动画。

## 3. 两页共用的 token 落点
- 命名要纠正：颜色主要映射 **`--dsw-*`**，字体为 **`--dsh-font-family-text/code`**，不要统一臆造 `--dsh-*` 颜色名。
- `alias-bg-base ← sand-bg-chrome`；`specific-sidebar-fill ← sand-bg-sidebar`；`alias-bg-layer-2 ← sand-bg-pane`；浮层/输入取 `sand-bg-elevated`。
- `alias-label-primary/secondary/tertiary ← sand-text-*`；hover/active 与 border-l3/l4 直接按 RE-theme §5 映射，保留透明度与叠加面。
- 用户泡 `specific-bubble ← sand-fill-bubble-user`；assistant 取 `sand-fill-bubble-agent`；浅色用户泡使用适配深底的前景，不能沿用深色正文。
- 正文 XVF、代码 XVF Mono，本地加载；图标走原版字形提取后的主题 sprite 替换，不混用另一套轮廓风格。
- 暗色关键层级为 sidebar `#0e0e0e`、chrome `#121212`、pane `#161616`、elevated `#1f1f1f`；暗色靠描边，不另加重阴影。
- 不继承 dsh 的 28px panel 圆角；按原版具体组件取值。侧栏动效 `.2s cubic-bezier(.22,1,.36,1)`，正文不逐 chunk 淡入。
- 窗口不足以同时容纳侧栏与 424px chat 时折叠侧栏，避免压坏正文；此响应规则为本提案，非已验证原版行为。

## 4. 反提案、差异与复用
- **反提案：不要把审批做成全局 modal。** 它会阻断其他 bot、丢调用上下文，也违背原版 inline 卡片结构；仅新建使用 modal。
- 已知差异：无账号/搜索/分组/拖拽/语音/附件/info-pane；是 P4 范围收窄，不用禁用入口模拟「完整原版」。
- 新建文案、固定配置说明、只读提示与本地断线提示为本产品差异；分别解决 1:1、契约限制、恢复失效与本地拓扑，不改审批策略。
- MIT 复用：`deepseek-ai/deepseek-harness@ce7073d:packages/client/ui-primitives/`（Modal/Button）、`ui-chat/`、`ui-conversation/`、`ui-tool/`、`ui-approval/`；运行时与业务订阅原样集成，不自写第二套状态机。
- Grok 资产为闭源版权资产，按本项目私用边界复用；`b-nett/grok-bot-0.18-reconstructed` 无 LICENSE，仅作静态参考，不作维护中依赖。
