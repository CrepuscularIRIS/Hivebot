== 实现说明 / 取舍 ==
- 捷径列的「第 1 级 subagent maxDepth / tools.restrict」评估后未用作主机制：
  maxDepth 是 preset 插件 config（全局，无法按会话只对 worker 关）；tools.restrict
  需要 agent scoped ctx（tools/index.ts:165 明确拒绝全局 restrict），profile 级
  插件拿不到 worker 的 scoped ctx。按 PLAN 任务定义以 pre-execute 执行层为主
  （对 worker 按会话判定），maxDepth 留给上游纵深。已按要求在报告注明。
- worker 判定复用 slots.readWorkerIds（bots.json createdBy），每次 execute 重读
  （无缓存窗口，worker 落盘即生效）；bots.json 不可读 → 不按 worker 拦（与
  slots 收养同口径，P5 guard 链 + 协调者工具自身 main 校验仍在）。
- 回调内不调宿主可重入 API（只读自己的 fs 与纯函数）。
- 已知上限（envelope.mjs ponytail 注）：subagent/workflow 的 toolName 可被 preset
  改名，名单跟 standard preset 缺省名；主 bot 不受信封约束（委派/后台照常）。
- envelope 仅在 orchestration.yml 加载时存在（P2SDK_PATCH / P6-14b 开放闸），
  默认链行为零变化（P6-10 起的同一约定）。
