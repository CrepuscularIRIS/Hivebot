## 必须回应清单（带证据的 HIGH；MEDIUM/LOW 见各席原文）

1. **[A-HIGH] host 不随 deb 发布**：`main-app.cjs:4` 显示 host 以 `incoming-host-bundle.tgz` 云端下发（`/opt/sand/sand-host/host-main.cjs`）；0.18 的 35 个扩展 id 中 11 个在 0.78.1 里 grep 0 命中。影响 host-ext、features Q1/Q2、marketplace Q3。→ DONE 允许「不可得 + 负证据」，此类结论标「0.18 推定」；禁止去拉 host-bundle。
2. **[A-HIGH] 锚点格式在 minify 产物上无区分度**：`preload.cjs` 仅 32 行、单行约 27 KB，「路径:行」与「grep -n 命中」几乎无信息量。→ 锚点主格式改 `路径#"字面串"`，命中定义 `grep -cF` ≥1。
3. **[A-HIGH] 模块 diff 粒度未定、基线不对**：0.18 reconstructed 是部分重构的 macOS 版。A 席称 0.18 原始 dmg/exe 本机就有（与 RE-unpack「无 dmg 源」结论冲突，需核实）。→ 固定 4 轴（依赖、chunk 语义名、preload 入口、proto 服务）直接对比两个原版 asar；diff 必须在 W1 派发前完成，否则与「清单主题不补派」冲突（D7）。
4. **[A-HIGH] MVP 旅程不全**：旅程③漏 roadmap.md:83「bot 能调用它的工具」与审批卡往返；另缺冷启动恢复（roadmap.md:82）与「选 agent 配置」（roadmap.md:7）。
5. **[A-HIGH] 路线 B 的核心产物「同/改/新/删」无 DONE 检查**。→ 加 D2b；标「同」的项也要附 0.78.1 锚点。
6. **[B-HIGH] 防漏机制不覆盖旧 bundle 内新增子系统**：W0 diff 只查目录 / bundle 级；D7 只查名称出现。→ 增加不依赖 0.18 的入口扫描（进程、路由、IPC/service、扩展），每个新能力映射到具体 RE 问题或非 MVP 清单行；W0 补全后才释放依赖它的任务。
7. **[B-HIGH] DONE 不验收答案完整性与证据支持度**：字符串存在即可过，错误的旅程方法表也能 PASS。→ 每题必须有答案 + 对照 + 证据，未知项显式列出；三条 MVP 旅程核验「调用方→方法→事件/返回」静态链路，关键断点未解不得 PASS。
8. **[C-HIGH] 同 B-6**：要求进程入口 / 语义子系统归属表；明确 `local-exec-daemon` 的归属（RE-unpack.md:66,117 已发现但拉起关系未验证）。
9. **[C-HIGH] MVP 最小接口面只有方法名**：无参数 / 返回结构 / 调用方与处理方对应。→ MVP 方法补参数与返回结构（或可定位 schema）+ 调用与处理锚点；抽查一条完整旅程而非五个孤立字符串。
